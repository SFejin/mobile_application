# WORK SAFE — 개발용 Android 베이스 앱

`LayoutImages/`의 SVG 시안을 Jetpack Compose로 구현한 로컬 데모 앱입니다.
로그인, 홈, 개인 정보 변경, 화면 모드 변경, 비밀번호 변경, 회원 탈퇴와
설정 메뉴·확인/성공/실패 다이얼로그를 라이트·다크 테마로 제공합니다.

낙상 감시와 BLE 비콘 수신·송신은 실제 Android API를 사용합니다.
BLE 거리·위치는 RSSI 기반의 **근사치**이며 안전 판단용이 아닙니다.
Galaxy Watch·생체 정보는 예시이고 서버 상태는 `DEMO · 미연결`입니다.

## 빌드와 실행

- JDK 17 또는 21, Android SDK Platform 35가 필요합니다.
- Gradle 8.9 Wrapper가 포함되어 있습니다. 최초 실행에는 의존성 다운로드가 필요합니다.
- Android Studio에서 저장소 루트를 열고 Gradle JDK를 17/21로 선택한 뒤 `app`을 실행합니다.
  JBR/JDK 25는 이 Gradle 버전과 맞지 않으므로 사용하지 않습니다.

macOS 설정:

```sh
export JAVA_HOME="$HOME/Library/Caches/worksafe-dev/jdk-21.0.13+9/Contents/Home"
export ANDROID_HOME="$HOME/Library/Android/sdk"
./gradlew --no-daemon :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

다른 환경에서는 `JAVA_HOME`과 SDK 경로를 설치 위치에 맞게 지정합니다.
생성되는 APK: `app/build/outputs/apk/debug/app-debug.apk`

에뮬레이터 또는 Android 8.0 이상 기기를 연결한 뒤:

```sh
"$ANDROID_HOME/platform-tools/adb" install -r app/build/outputs/apk/debug/app-debug.apk
"$ANDROID_HOME/platform-tools/adb" shell am start -W -n com.example.safetymonitor/.MainActivity
```

여러 기기가 연결되어 있으면 adb 명령에 `-s <기기 시리얼>`을 추가합니다.

## 데모 계정과 상태 수명

| 항목 | 동작 |
|---|---|
| 초기 로그인 | 작업자 ID `1024`, 비밀번호 `0000` |
| 초기 프로필 | 홍길동 / 남 / 29 / 사원 / 생산1팀 |
| 개인 정보 | 이름·성별 공백 및 1~120 범위 밖 나이를 거절하며, 저장 후 홈과 헤더에 반영 |
| 비밀번호 | 현재 비밀번호, 새 비밀번호 4자 이상, 확인 일치를 검증 |
| 로그아웃 | 로그인 화면으로 이동. 계정·프로필·변경 비밀번호는 유지 |
| 회원 탈퇴 | 확인 후 현재 프로세스의 데모 계정을 비활성화. 재로그인 거절 |
| 테마 | SharedPreferences에 저장. 프로세스 재시작 후에도 유지 |

계정·프로필·비밀번호는 **프로세스 메모리에서만** 유지합니다.
화면 회전이나 Activity 재생성만으로 초기화되지 않으며, 비밀번호를 디스크에 저장하지 않습니다.
실제 서버 계정은 생성·수정·삭제하지 않습니다.

프로세스 종료 후에는 초기 데모 계정으로 복원됩니다.
최근 앱 화면에서 닫는 것만으로 프로세스 종료가 보장되지는 않으므로,
개발 중 확실하게 초기화하려면 다음을 사용합니다. 테마는 초기화하지 않습니다.

```sh
"$ANDROID_HOME/platform-tools/adb" shell am force-stop com.example.safetymonitor
"$ANDROID_HOME/platform-tools/adb" shell am start -W -n com.example.safetymonitor/.MainActivity
```

## BLE 거리·2D 위치 데모

동일 앱의 송신 모드가 내보내는 전용 UUID·8바이트 Service Data만 처리합니다.
임의 BLE 기기나 상용 iBeacon/Eddystone을 자동으로 거리 측정하는 기능은 아닙니다.

### 수신 — 기본 모드

- 로그인 후 기본 역할은 수신입니다. 권한이 없으면 홈에서 차단 사유와 사용자 조작을 표시하며, 권한을 임의로 허용하거나 반복 요청하지 않습니다.
- Android 12 이상은 주변 기기 검색과 정확한 위치 권한, Android 8~11은 위치 권한이 필요합니다. 위치 서비스와 Bluetooth도 켜져 있어야 합니다. 백그라운드 위치의 ‘항상 허용’은 요구하지 않습니다.
- 홈에 실제 비콘 ID·송신 좌표·RSSI 중앙값·추정 거리·최근 관측을 표시합니다. 최근 최대 5개 RSSI의 중앙값과 `d = 10^((A - RSSI) / (10 × 2))`를 사용합니다. `A`는 **1m 기준 RSSI**이며 송신 출력 설정이 아닙니다.
- 최신·유효·고유 ID의 사용 가능한 비콘 수에 따라 표시를 바꿉니다.
  - **0개 — 위치 미확정:** 이전 위치 점이나 거리 원을 남기지 않습니다.
  - **1개 — 비콘 거리 참고:** 고정 비콘의 ID·추정 거리와 참고 원을 표시합니다. 작업자 좌표나 사용자 점은 만들지 않습니다.
  - **2개 — 가중 참고 위치:** `1/d` 역거리 가중 비콘 중심점을 마름모로 표시합니다. 두 거리 원의 교차해나 유일하게 측정된 실제 위치가 아닙니다.
  - **3개 이상 — 2D 근사 위치:** 기존 삼변측량 솔버가 성공하면 근사 위치 점을 표시합니다. 일직선 배치 등으로 실패하면 원래 실패 사유와 함께 가중 참고 위치로 낮춥니다.
- 좌표는 송신기에 설정한 공통 기준의 미터 단위이며 GPS·지도 좌표가 아닙니다. 일반 BLE RSSI만으로 방향은 알 수 없습니다. 거리 원은 실제 위치의 보장 경계나 통계적 신뢰구간이 아닙니다.
- 표본의 나이가 5초를 초과하면 만료합니다. 동일 ID의 좌표·기준 RSSI가 충돌하면 해당 비콘만 계산에서 제외합니다. 남은 사용 가능한 비콘 수에 맞춰 표시를 낮추며 이전 좌표를 현재 위치인 것처럼 유지하지 않습니다.
- 화면의 일반 주의 문구는 `장애물과 환경에 따라 오차가 발생할 수 있습니다.` 한 줄로 표시합니다. 권한 차단·실제 오류·잘못된 입력 안내는 유지합니다.

### 숨김 송신 모드

1. 로그인한 홈의 `WORK SAFE` 제목을 **3초 안에 7번** 누르면 송신 설정을 엽니다. 설정 진입이나 값 저장만으로 송신하지 않으며 기존 수신을 유지합니다.
2. 기본 화면에서 송신기 ID `1~65535`와 1m 기준 RSSI를 설정합니다. 기준 RSSI는 `-127~-1dBm`, 기본값은 보정되지 않은 예시 `-59dBm`입니다. 설치 X/Y는 **고급 설정**을 펼칠 때만 보입니다. 좌표 범위는 `-327.68~327.67m`이며 cm 단위로 반올림해 저장합니다.
3. 명시적으로 송신을 시작하고 필요한 광고 권한을 허용합니다. 광고 시작 콜백이 성공해야 송신 중으로 표시합니다. 송수신은 동시에 실행하지 않습니다.
4. 송신 중지 또는 수신 복귀를 선택할 수 있습니다. 설정만 저장하고 송신하지 않는 상태도 허용합니다. 송신 설정은 저장되지만 실행 여부는 저장하지 않으므로 새 프로세스·재부팅 뒤 자동 송신하지 않습니다.

고급 설정을 접어도 저장값과 입력 중인 좌표는 유지됩니다. 좌표가 잘못되면 오류와 필드가 보이도록 접기를 막습니다. 새 설정의 기본 좌표 `(0,0)`은 원점이지 ‘미사용’ 표시는 아닙니다. 거리 측정만 사용할 때는 그대로 두어도 되지만, 2D 위치 계산에는 비콘별 공통 기준 배치 좌표가 필요합니다.

거리 시연은 수신기 1대와 광고를 지원하는 송신기 1대로 시작할 수 있습니다. 가중 참고 위치에는 송신기 2대, 삼변측량 근사 위치에는 서로 다른 ID와 적절한 배치의 송신기 3대 이상이 필요합니다. 비콘 수가 늘어도 정확도 향상이 보장되지는 않습니다.
예를 들어 ID 1을 `(0, 0)m`, ID 2를 `(4, 0)m`, ID 3을 `(0, 3)m`에 고정하고 실제 배치도 맞춥니다.
반사·벽·사람·기기 방향에 따라 RSSI와 위치가 크게 흔들릴 수 있습니다. 1m 기준 RSSI도 실제 환경에 맞춰 보정해야 합니다.

### 화면 꺼짐·중지·정보 범위

- 화면이 보일 때 시작한 BLE 포그라운드 서비스가 앱 전환·화면 꺼짐 뒤에도 동작하도록 구성했습니다. 수신은 `location|connectedDevice`, 송신은 `connectedDevice`를 사용하며 기존 낙상 서비스와 분리됩니다.
- BLE 알림의 중지 또는 앱의 중지는 BLE만 멈춥니다. 로그아웃·탈퇴는 BLE도 종료합니다. 명시적 중지 뒤 앱을 다시 보는 것만으로 자동 재시작하지 않습니다.
- 권한 거절·지원 불가·초기 Bluetooth/위치 꺼짐은 차단 상태와 조치로 안내합니다. 설정을 해결한 뒤 앱으로 돌아와 필요한 시작 동작을 수행합니다. 강제 종료·재부팅·시스템의 서비스 종료 뒤 무인 복원을 보장하지 않습니다.
- 알림 권한을 거절하면 알림 표시가 제한됩니다. 포그라운드 서비스가 유지돼도 OS가 스캔 주기를 낮출 수 있으므로 화면 꺼짐 중 고정 주기의 위치 갱신은 보장하지 않습니다. 각 비콘의 새 표본이 5초를 초과해 없으면 해당 비콘이 만료되어 표시 단계가 낮아지거나 위치 미확정이 됩니다. 실제 수신 지속과 배터리 영향은 OS·기기별로 실측해야 하며, 절전 예외나 권한을 강제로 설정하지 않습니다.
- 광고에는 버전·ID·좌표·기준 RSSI만 평문으로 들어갑니다. 주변에서 읽거나 위조할 수 있으므로 민감한 실제 위치·식별 정보를 넣지 마세요. GPS·계정 정보·위치 이력을 수집하거나 서버에 보내지 않습니다.

### BLE 검증 범위

- JVM 단위 테스트 **11개(추정기 7개·프로토콜 4개)**에서 패킷 경계/오류, RSSI 중앙값·만료·순서, ID 충돌 복구, 0→1→2→3→2→1→0 전환, 역거리 가중값, 정상/퇴화 기하·영역 밖 해와 3개 이상 실패 시 사유를 보존한 가중 전환을 확인했습니다. 이는 실제 송신기 3대의 무선 검증이 아닙니다.
- 통합 `testDebugUnitTest`, `assembleDebug`, `lintDebug`가 성공했습니다.
- Pixel_4a 에뮬레이터(API 37)에서 권한 미허용 상태, 7탭 진입 후 송신 대기, 송신 시작 권한 거절과 홈의 차단 상태, 음수·소수 좌표 입력, 앱 내부 라이트·다크 전환을 실제 화면으로 확인했습니다. 이 검증에서는 BLE 권한을 허용하지 않았고 스캔·광고 성공을 확인한 것은 아닙니다.
- 같은 에뮬레이터에서 Android 설정 UI로 승인된 권한만 허용한 뒤 실제 스캔 시작과 광고 성공 콜백(`status=0`), 송수신 배타 전환, 앱의 송신 중지·알림의 수신 중지, 중지 후 재진입, 새 프로세스의 기본 수신/자동 송신 없음도 확인했습니다.
- 화면을 6분 이상 끈 추가 시험에서 수신 스캐너 등록·서비스는 유지됐지만, 스캔 시작 약 5분 뒤 실제 모드가 `LOW_LATENCY → LOW_POWER`, 이후 `SCREEN_OFF`로 낮아진 것을 Bluetooth 로그로 확인했습니다. 스캔 중단이나 `OPPORTUNISTIC` 전환은 아니었습니다. 이 에뮬레이터에서 관측한 `SCREEN_OFF` 스캔 간격은 약 10.24초로 5초 표본 만료보다 길어, 위치가 계속 확정된다고 보장할 수 없습니다. API 37 이미지의 결과이며 S23U에서도 동일한 제한 시간·주기라고 단정하지 않습니다.
- 필터가 있는 스캔의 시간 초과 시 저전력 전환은 [고정 리비전의 AOSP `ScanManager`](https://android.googlesource.com/platform/packages/modules/Bluetooth/+/c77db469de80f86660bc053bec4dee0c5d4b947c/android/app/src/com/android/bluetooth/le_scan/ScanManager.java)과 대조했습니다. 서비스 생존·스캐너 등록·요청한 `LOW_LATENCY` 모드만으로 실제 무선 수신 빈도를 입증할 수 없습니다.
- 위 에뮬레이터 시험에서는 화면 꺼짐 중 광고가 25초 동안 유지됐습니다. 당시 실제 송신기가 없어 RSSI 콜백·거리·위치 갱신을 확인한 것은 아닙니다. 에뮬레이터의 서비스 생존이나 광고 성공 콜백을 실물 RF 송수신 증거로 해석하지 않습니다.
- 초기 단계형 APK에서 S23 Ultra SM-S918N(API 36)를 수신기로, Xperia 1 J9110(API 30)의 ID 1 `(0,0)m`와 Tab S10 Ultra SM-X926N(API 36)의 ID 3 `(0,3)m`를 실제 송신기로 사용했습니다. 두 송신기의 예시 기준 RSSI는 `-59dBm`입니다. 수신 없음 → 1개 거리 참고 → 2개 가중 참고 위치 → 송신기 1대 중지 뒤 1개 → 나머지 중지 뒤 미확정 전환을 확인했습니다. 중지 후 화면 캡처는 약 9초 뒤이므로 정확한 만료 지연을 측정한 것은 아닙니다.
- 지도 표시 개선 단계에서 검증한 APK의 SHA256은 `4767449fca8bf0ce5558f409687544deca25b1f0a5b10868650e5fe2b04b619e`입니다. 이 APK의 빌드·lint 및 승인된 세 기기의 데이터 보존 설치가 성공했습니다. 실제 1비콘 거리 참고와 2비콘 가중 참고 위치, 방향 미확정 안내 및 ID/좌표 목록을 확인했습니다.
- 지도 내 마커 글자를 기존 비콘 목록으로 분리하고 윤곽 마름모를 사용한 뒤, 실제 2비콘 화면에서 가까운 앵커 중심·마름모·카드·고정 범례를 식별할 수 있었고 글자 겹침이 없었습니다. 이 단계의 캡처는 원이 경계를 가로지르는 장면이 아니므로, 이전 APK에서 확인한 경계 clip 증거와 구분합니다. 시험 후 세 기기의 BLE를 정상 중지했고 기존 낙상 서비스만 남았으며, 실행한 호스트 헬퍼는 없습니다.

## 실시간 센서 화면 및 Android Studio 실행

- 프로젝트 루트(`settings.gradle.kts`가 있는 폴더)를 Android Studio에서 엽니다.
- Gradle JDK는 17 또는 21을 선택합니다. 현재 Gradle 8.9/Kotlin 2.0.20 구성에서 JDK 25는 사용하지 않습니다.
- Gradle Sync 후 `app` 실행 구성을 선택해 실행합니다. 데모 로그인: ID `1024`, 비밀번호 `0000`.
- 로그인 후 기존 홈 화면의 가속도 센서 행에 가속도 합성값(m/s²)이 약 100ms 간격으로 표시됩니다. 자이로 센서는 내부 낙상 판정에 사용하며 별도 표시 영역은 추가하지 않습니다. 가속도는 중력을 포함하므로 정지 시 합성값은 약 9.81m/s²입니다.
- 낙상 판정은 가속도계의 자유낙하/충격, 자이로의 큰 회전, 두 센서의 3초 정지를 확인합니다. 한 센서가 없거나 등록에 실패하면 낙상 감지를 비활성화하고, 사용 가능한 센서 값은 계속 표시합니다.
- 두 센서 모두 새 값을 수신해야 판정하며, 한 센서 값이 500ms 이상 지연되면 진행 중인 판정을 초기화합니다.
- 로그인하면 알림을 표시하는 포그라운드 서비스에서 측정을 시작합니다. 다른 화면/앱으로 이동하거나 화면을 잠그거나 최근 앱에서 화면을 제거해도 측정을 계속합니다. 로그아웃 또는 회원 탈퇴 시 서비스·센서·알림을 종료합니다. 앱을 다시 열면 측정 세션과 최신 값이 연결됩니다. Android 13 이상에서는 측정 알림 권한을 요청하며 거부하더라도 측정은 계속됩니다. 기기 재부팅이나 시스템 설정에서 앱 강제 종료 후에는 앱을 다시 열어야 합니다. 현재 변경은 화면의 실제 감지 표시이며 서버 전송은 연결하지 않습니다.

## 작업자 서버 API 통신 계층

`network/WorkerApiClient.kt`와 `WorkerApiModels.kt`는 작업자 API 호출을 위한 독립 통신 계층입니다. 서버 계약은 `mobileProgrammingTeam/server`의 기본 프로젝트만 있는 `main`이 아니라 [master의 고정 리비전 `42f2a75190db910e6fee29082494d927a4ef9e02`](https://github.com/mobileProgrammingTeam/server/tree/42f2a75190db910e6fee29082494d927a4ef9e02)을 기준으로 합니다. 현재 데모 로그인·UI·센서와 자동 이벤트 전송에는 연결되지 않았으며 기존 `AlertSender`도 그대로입니다.

| 메서드 | 경로 | 성공 | 요청 / 응답 DTO |
|---|---|---:|---|
| POST | `/api/worker/auth/login` | 200 | `WorkerLoginRequest` / `WorkerTokenResponse` |
| POST | `/api/worker/auth/logout` | 204 | 없음 / 없음 |
| POST | `/api/worker/events` | 201 | `WorkerEventRequest` / `WorkerEventInfo` |
| PATCH | `/api/worker/me` | 200 | `WorkerProfileUpdate` / `WorkerInfo` |
| PATCH | `/api/worker/me/password` | 204 | `WorkerPasswordChange` / 없음 |
| DELETE | `/api/worker/me` | 204 | `WorkerPasswordConfirmation` / 없음 |

호출자가 서버 루트 `baseUrl`을 제공합니다. 기본값은 HTTPS만 허용하며 로컬 개발 HTTP는 `allowInsecureHttp = true`로 명시적으로 선택해야 합니다. HTTP는 암호화되지 않으므로 실제 비밀번호나 토큰에 사용하지 마세요. 클라이언트는 무상태이며 로그인 외 보호 호출마다 호출자가 access token을 전달합니다. 토큰 저장·갱신·프로필 GET은 제공하지 않으며, 만료와 인증 실패에 대한 처리는 호출자가 담당합니다.

호출 예시는 코루틴 내부에서 실제 배포 환경의 `serverRoot`, `workerId`, `password`를 호출자가 제공하는 경우입니다.

```kotlin
val api = WorkerApiClient(baseUrl = serverRoot)
val session = api.login(WorkerLoginRequest(workerId, password))
val updated = api.updateProfile(session.accessToken, WorkerProfileUpdate(workerName = newName))
api.logout(session.accessToken)
```

HTTP 실패는 `WorkerApiException`의 상태 코드와 서버가 제공한 코드·메시지로 전달되며 통신 실패와 취소는 호출자에게 전파됩니다. 자동 리디렉션과 애플리케이션 수준 재시도는 없고, 본문은 UTF-8 고정 길이 스트리밍으로 전송합니다. 플랫폼의 연결 복구까지 완전히 막거나 서버가 요청을 정확히 한 번만 처리한다고 보장하지 않습니다. 타임아웃·취소 시 서버 처리 여부는 불확실할 수 있습니다.

이번 API 계층은 debug 빌드와 네트워크 없는 생성자·입력 검증·민감 문자열 마스킹 초기화 확인만 수행했습니다. Android JSON 런타임, 실제 HTTP/TLS 통신, 인증·서버 오류·취소·라이프사이클 및 실제 서버 계약 일치는 검증하지 않았습니다. 이 결과는 앱의 서버 연결이나 이벤트 전송 성공을 의미하지 않습니다.
