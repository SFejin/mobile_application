# 심박수·위험 비콘 자동 알림

기존 낙상 SOS와 별도로 로그인한 작업자의 foreground 감시 서비스에서 평가하고,
기존 `POST /api/worker/events`에 Bearer 토큰으로 전송한다.
서버 `dev-juhyun`의 `a73db82`(2026-11-27) 계약에 맞춰 `POST /api/worker/me/status`도 사용한다.
심박·손목 피부 온도 SOS와 작업 종료 확인 무응답은 서버 접수를 확인하면 긴급재난문자 알림음을 한 번 재생한다.

## 사용

- 앱의 고정 심박 확인 기준과 진행 중인 위험 구역 작업은 홈에 표시한다.
- **50 bpm 미만 또는 120 bpm 초과**인 구간이 같은 방향으로 연속 두 번 확인되면 위험 상태와 이벤트를 전송한다. 50과 120은 정상에 포함한다. 구간당 유효 심박 샘플은 3개 이상이어야 한다. 첫 이상 구간의 30초 무응답으로 심박 이벤트를 보내던 동작은 최신 서버 판정 계약에 맞춰 제거했다.
- `EventSettings.fixedConfig`가 유일한 실행 기준이다. 기존 사용자 설정 파일 `vital_alert_limits` 및 피부온도 환경별 프로필은 읽지 않는다. 고정 기준을 바꾸려면 코드 변경과 재빌드가 필요하다.
- 심박수는 5분 평균이므로 두 구간(보통 10분)에 대한 판정이며 순간 이상을 즉시 알리는 기능은 아니다. 연속 구간은 서로 겹치지 않고 이전 종료와 다음 시작 간격이 1분 이하이며 요약 간격이 같아야 한다.
- 중복/역순 timestamp, 누락·오래된 값은 이벤트 근거로 쓰지 않는다. 같은 이상 상태에서는 반복 전송하지 않고 정상 범위의 새 값을 확인한 뒤 재감지한다.
- 손목 피부 온도는 주변온도가 비슷한 환경의 개인 기준선 대비 ±2°C 이상이 같은 방향으로 연속 두 구간에서 관측되면 알림을 전송합니다. 초기 기준선 준비와 제한 사항은 아래 **생체 신호 테스트 및 손목 온도 기준**을 참고하세요.
- **50/120은 개발용 고정값이며 의학적 진단 기준이 아니다.** 작업 강도·개인차를 고려한 현장 검증 전에는 검증된 응급 감지 기능으로 간주하지 않는다.
- 기존 제목 7회 탭 이스터에그에서 비콘 유형을 **일반 / 위험 경고**로 선택하고 저장·송신한다.
  송신 중에는 변경할 수 없다. 위험 비콘 신호를 수신한 다른 앱에서만 접근을 감지한다.
- 위험 비콘에 추정 2m 이내로 접근한 첫 유효 신호에서 진동과 **통과 / 작업 시작**을 표시한다. 접근 확인은 30초 동안 표시한다. 작업은 비콘 근처에서 5·10·15·30분 중 선택한다.
  접근 확인에 응답이 없으면 관리자가 확인할 수 있도록 이벤트를 전송한다. 휴대폰은 최초 진동과 접수 결과만 표시한다.
  시간이 끝나기 전에 홈에서 **작업 끝**을 누르려면 해당 비콘의 유효한 근접 신호가 필요하다.
  시간이 끝나면 진동으로 다시 확인하고, 30초 동안 **작업 끝 / 5분 연장**에 응답이 없으면 전송한다.
  3m 이상 이탈이 유효 신호 3개 이상, 3초 이상 확인되면 접근을 다시 감지한다.
  BLE 거리는 RSSI 추정값이며 실제 거리는 기기·환경에 따라 달라진다.
- 홈에서 최근 5개 이벤트의 전송 결과를 확인한다(메모리에는 최대 20개).
  로그아웃/계정 변경 시 기록과 감지 상태를 초기화한다. 작업 타이머는 감시 서비스가 실행되는 동안 유지된다.
  앱이 백그라운드에 있으면 알림을 탭해 확인 창을 연다.

## 서버 계약

실제 센서 시작 확인 후 RUNNING, 감시 종료 시 STOPPED를 보고한다. 로그아웃은 중지 보고 시도를 기다린 뒤 인증을 해제한다. 강제 종료·통신 단절·인증 만료에서는 중지 보고가 보장되지 않는다.
새 워치 요약 수락 시 상태 요청을 한 번 보내며, `devices`에는 `type: "워치"`와 휴대폰의 실제 수락 시각 `lastSeenAt`만 넣는다.
확정한 심박 판정은 `heartRateStatus: NORMAL|DANGER` 및 구간 종료 시각 `measuredAt`을 함께 보낸다. 미측정·샘플 부족·첫 이상·만료·연속성 불충족이면 둘 다 생략하며, 정상으로 임의 보정하지 않는다.
감시 상태의 `reportedAt`과 측정 시각은 구분한다. 기존 측정 시각을 타이머나 재연결 시각으로 갱신하지 않는다. 상태 보고는 이벤트를 생성하지 않으므로 확정 위험은 기존 이벤트 API에도 별도로 한 번 전송한다.
상태 요청은 직렬로 처리하고 계정 전환 후 대기 중인 이전 계정 요청을 폐기한다. 실패한 요청은 자동 재전송하지 않으며 다음 새 상태를 보고한다. 홈에서 상태 전송 결과를 확인할 수 있다.

한글 심박 발신명을 사용하기 전에 서버에 영문·한글 호환 변경을 적용한다.

| 감지 | eventType | alertSender |
|---|---|---|
| 심박수 | ABNORMAL_VITAL | 심박수 이상 SOS |
| 손목 피부 온도 | ABNORMAL_VITAL | 체온 이상 SOS |
| 위험 구역 접근 확인 무응답 | DANGER_ZONE_APPROACH | 위험지역 침입 · 비콘 #{ID} |
| 위험 구역 작업 종료 확인 무응답 | DANGER_ZONE_APPROACH | 위험지역 작업 시간 초과 무응답 · 비콘 #{ID} |

`time`은 앱이 이상을 확정한 UTC 시각이다. 기존 계약에는 측정값 필드가 없으므로
수치 자체는 서버에 전송하지 않는다. 통신 오류/5xx는 접수 여부 불명으로 표시하고
자동 재전송하지 않는다. 최신 서버는 동일 심박 이벤트의 작업자·유형·발신자·발생 시각 조합을 중복 제거하지만 다른 유형에는 일반화하지 않는다. 401은 세션을 무효화한다.
개발 로그인은 실제 서버 요청을 하지 않는다. 서비스 중지 시 추가 감지도 중지된다.

## 비콘 호환성

8바이트 길이와 ID/좌표/RSSI 배치를 유지한다. 첫 바이트 1은 기존 일반 비콘,
2는 위험 비콘이다. 이전 수신 앱은 2를 무시하므로 **송신·수신 앱 모두 업데이트**해야 한다.
기존 저장 설정과 버전 1 신호는 일반 비콘으로 취급한다. 동일 ID의 유형/좌표 충돌은
기존 비콘 충돌 검사로 제외한다.

## 기기 검증

실제 서버 계정과 업데이트한 송신·수신 기기에서 위험 접근/일반 비콘 제외,
화면을 끈 상태의 워치 수신, 실제 서버 이벤트 접수를 확인해야 한다.
단위 테스트는 감지 조건·중복/누락/만료·인증·전송 계약을 검증하며 실제 기기를 대체하지 않는다.


## 생체 신호 테스트 및 손목 온도 기준 (2026-11-28)
- 홈의 **생체 신호 / 센서 정보** 제목을 3초 안에 7번 누르면 테스트 창이 열린다. 심박수/손목 온도를 선택하고 실행한다. 실제 로그인에서는 `ABNORMAL_VITAL`과 `심박수 이상 SOS · 테스트` 또는 `체온 이상 SOS · 테스트`를 전송한다. 접수 후 알림음이 울린다. 개발 로그인에서는 서버에 보내지 않는다. 10초 실행 간격이 있다.
- 테스트는 별도 감지기에 가상 구간을 입력한다. 실제 워치 데이터, 운영 감지기, 서버 심박 상태 요약을 변경하지 않는다. 실제 BLE/워치 수신이나 서버의 영문 심박 발신명 전용 처리는 검증하지 않는다.
- 기존 34°C 고정 기준 대신 손목·주변 온도를 함께 사용한다. 워치 주변온도 ≤15°C는 저온, ≥30°C는 고온, 그 사이는 일반 환경으로 분류한다. 환경이 바뀌거나 기준선의 주변온도에서 3°C 이상 달라지면 기준선을 폐기하고 다시 준비한다. 이전 환경의 기준선은 재사용하지 않는다.
- 같은 환경의 유효한 연속 5분 구간 6개(약 30분)로 기준선을 만든다. 손목 값 범위 ≤1°C, 주변 값 범위 ≤2°C일 때 손목 중앙값을 기준으로 삼는다. 불안정하면 이동 창으로 다시 평가한다. 기준선 준비 중, 측정 누락·지연 시 온도 이상 판단은 대기한다. 심박수 감지는 계속된다. 기준선 대비 **±2°C 이상이 같은 방향으로 연속 두 구간**에서 관측되면 `ABNORMAL_VITAL` / `체온 이상 SOS`를 전송하고 접수 후 알림음을 울린다. 방향별 중복을 막고 절대 편차가 1.5°C 미만으로 회복되면 재알림할 수 있다. 누락·끊김은 연속 확인이나 회복으로 처리하지 않는다.
- 15/30°C 환경 구분, 3°C 환경 변화, 30분 준비, 안정 범위 1/2°C, 변화 2°C, 회복 1.5°C는 모두 **미검증 연구용 파라미터**이며 의료 표준이 아니다. 삼성 센서는 손목 근처 주변온도이며 작업장 기온이나 WBGT 측정값이 아니다. 주변온도를 빼서 체온으로 환산하거나 더운 환경에서 경고 기준을 완화하지 않는다. 각 온도는 구간의 마지막 유효값이므로 10분 내내 이상이 지속됐다는 뜻이 아니다. 초기부터 과열/냉각된 상태에서 보정하면 이상을 놓칠 수 있고 환경 변화 때마다 약 30분 이상 판단 공백이 생길 수 있다. 감시 시작·환경 변경 후 안정된 상태에서 준비하고 준비 중 표시를 확인한다. 피부온도로 발열·열사병·저체온증을 진단할 수 없다.
- 근거: 손목 온도는 구강 온도와 다르고 개인/환경 변동이 크다. 아래 연구는 개인 내 변화 사용의 근거이며 위 숫자를 검증한 자료가 아니다.
  - https://pmc.ncbi.nlm.nih.gov/articles/PMC8293303/
  - https://www.nature.com/articles/s41467-023-40977-5
  - https://www.cdc.gov/niosh/docs/2016-106/pdfs/2016-106.pdf

주변온도 센서의 의미: https://developer.samsung.com/health/sensor/guide/data-specifications.html (위 수치의 임상 근거를 제공하는 자료는 아님).

### SOS 접수 알림음 해제

- 낙상·심박수·손목 온도·위험구역 작업 종료 무응답 SOS가 접수되면 SOS 알림음을 반복 재생합니다. 접수 후 진동은 추가하지 않습니다.
- 해제 창에 표시된 `0000`을 입력하고 **알림음 끄기**를 누르세요. 뒤로가기나 창 바깥 터치로 해제되지 않습니다. 코드가 다르면 해제 버튼이 활성화되지 않습니다.
- SOS 알림음만 종료하며 서버 SOS 기록은 유지합니다. 코드 입력은 보안 인증이 아닌 실수 방지 절차입니다.
- 위험구역 최초 접근 무응답의 조용한 관리자 알림은 유지합니다. 새 낙상 취소 대기 중에는 진동 확인을 우선하며 접수 알림은 이후 다시 재생합니다. 서비스 종료 시에는 재생 자원을 정리합니다.

### 통합 감지 상태와 작업 시간 초과 테스트

- 홈 실시간 감지 상태에서 낙상·심박수·손목 온도·위험구역 상태를 함께 확인합니다. 작업 중에는 비콘별 남은 시간과 작업 끝 버튼이 표시됩니다. 수신 대기/기준선 준비는 정상 판정과 구분합니다.
- 생체 신호 제목을 3초 안에 7번 누르는 테스트 창에서 진행 중인 비콘 작업의 **남은 시간 1초**를 누르면 해당 작업만 단축합니다. 기존 작업 종료 확인 30초는 유지됩니다. 무응답 시 실제 로그인에서는 테스트 표시가 붙은 SOS를 보내고 접수 알림음을 재생합니다. 개발 로그인에서는 전송하지 않습니다.

### 간결한 실시간 상태 카드

- 상단 카드는 현재 상태명과 진행 배지만 표시하며 센서별 상세 문구는 나열하지 않습니다. 작업 남은 시간/작업 끝은 기존 자동 알림 카드에서 확인합니다.
- SOS 전송 중 또는 접수 알림음 재생 중에는 낙상·심박수 이상·체온 이상·위험구역 작업 시간 초과 원인을 표시합니다. 해제 창에도 원인을 표시하며, 알림음 해제 후에는 작업 중/감시 중 상태로 돌아갑니다. 여러 이벤트가 겹치면 전송 중 이벤트를 우선 표시합니다.
