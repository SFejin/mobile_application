# 낙상 기반 자동 SOS

## 사용 방법

1. 기존 앱 데모 계정으로 로그인합니다. 초기 ID는 `1024`, 비밀번호는 `0000`입니다.
2. 홈의 **자동 SOS → SOS 서버 연결**을 엽니다.
3. 기본 서버 `http://34.22.75.168:8081`과 관리자가 발급한 **실제 서버 작업자 ID/비밀번호**로 연결합니다.
4. 홈에 표시되는 **전송 계정 ID**를 확인합니다. 앱 데모 프로필과 SOS 전송 계정은 별도입니다.
5. 낙상이 감지되면 20초 동안 휴대폰 알람·진동과 취소 안내가 표시됩니다. **괜찮아요 · 취소**는 앱 또는 알림에서 실행할 수 있습니다.
6. 취소하지 않으면 서버로 `FALL_DETECTED` 이벤트를 한 번 전송합니다. 서버가 정상 접수한 경우 이벤트 번호가 표시됩니다.

디버그 APK의 **알람 연습 · 서버 전송 없음** 버튼은 동일한 대기·취소 흐름을 사용하지만 실제 이벤트를 전송하지 않습니다. 종료·취소 후 30초 동안 같은 알람의 반복 시작을 억제합니다. 연습 중에는 실제 낙상 이벤트도 기존 대기에 합쳐지므로 작업 중이 아닌 때 연습하세요.

## 서버 계약

- 로그인: `POST /api/worker/auth/login`, JSON `workerId`(숫자), `password`.
- 이벤트: `POST /api/worker/events`, `Authorization: Bearer <accessToken>`.
- 본문: `time`(낙상 시각의 ISO-8601 UTC 문자열), `eventType: FALL_DETECTED`, `alertSender: ANDROID_AUTO_SOS`.
- 작업자는 요청 본문의 ID가 아닌 인증 토큰으로 식별됩니다.
- HTTP 201 및 응답의 작업자/이벤트 종류를 확인한 뒤에만 접수 완료로 표시합니다.
- 서버 코드 변경은 필요 없습니다. 관리자 웹에서는 기존 낙상 이벤트 목록으로 조회합니다. 별도의 `AUTO_SOS` 이벤트 종류나 관리자 푸시·소리 알림은 추가하지 않았습니다.

## 상태와 수명

- 서비스가 감지·대기·전송을 담당하므로 화면 회전이나 앱 화면 이동에 타이머가 종속되지 않습니다.
- 대기 중에는 중복 감지가 타이머를 연장하거나 전송 계정을 바꾸지 않습니다. 전송이 시작된 후에는 취소할 수 없습니다.
- 낙상 당시 연결된 서버 계정으로 전송합니다. 연결이 없거나 인증이 만료되면 전송 실패를 표시합니다.
- 인증 토큰과 비밀번호는 디스크에 저장하지 않습니다. 프로세스가 종료되면 서버 계정을 다시 연결해야 합니다. 로그아웃은 연결을 해제하고 서버 토큰 폐기를 시도합니다.
- 최근 SOS 결과는 로컬에 저장합니다. 대기 중 프로세스가 종료되면 다음 실행 시 중단/미전송으로 표시하며, 전송 중 종료되면 접수 확인 필요로 표시합니다. 재부팅·강제 종료 후 자동 전송 복구는 제공하지 않습니다.
- 통신 끊김·서버 오류는 이미 접수되었을 가능성이 있으므로 자동 재시도하지 않습니다. 관리자 화면에서 확인해야 합니다. 서버에 idempotency key 지원을 추가하면 안전한 재전송을 확장할 수 있습니다.
- 알림 권한이 꺼져 있으면 백그라운드 취소 알림이 표시되지 않습니다. 시스템 설정에서 알림을 허용하세요. 소리·진동은 기기 설정과 하드웨어 영향을 받습니다.
- 제공된 서버 주소는 HTTP입니다. 인증 정보의 암호화 전송이 필요한 배포에서는 HTTPS 주소를 사용하세요.

## 검증

JDK 17 또는 21과 Android SDK 35 환경에서:

```powershell
.\gradlew.bat --no-daemon :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
```

JVM 테스트는 취소, 대기시간, 중복 감지, 이전 알림의 취소 요청, 전송 후 취소 차단, 프로세스 종료 복구, HTTP 인증/이벤트 규격, 401/500/응답 유실/응답 불일치/만료를 검사합니다. HTTP 테스트는 로컬 모의 서버만 사용합니다.

기기 테스트는 기존 `BackgroundMonitoringTestRunner`에 SOS 검사를 연결했습니다. 앱과 androidTest APK를 테스트 기기에 설치하고 아래 명령으로 실행합니다. 테스트는 앱의 데모 로그인/로그아웃, 알람 연습, 화면 잠금을 수행하므로 실제 작업 중인 기기에서 실행하지 마세요.

```powershell
adb shell am instrument -w com.example.safetymonitor.test/com.example.safetymonitor.BackgroundMonitoringTestRunner
```

이 작업 환경에서는 에뮬레이터 가속 드라이버가 없고 연결 기기도 없어 기기 테스트를 실행하지 못했습니다. 실제 화면, 소리·진동, 잠금 화면 취소, 실제 계정으로 관리자 웹에 도착하는지는 실기기 확인이 필요합니다. 배포 서버의 `/health` 응답은 HTTP 200 및 `UP`을 확인했습니다.
