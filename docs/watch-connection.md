# 워치 수신 연결

## 준비

휴대폰 applicationId는 `com.example.safetymonitor`이며 수정한 워치 앱도 동일합니다.
두 APK는 같은 인증서로 서명해야 합니다. 같은 PC의 기본 debug 빌드는 동일한
`~/.android/debug.keystore`를 사용합니다. 다른 PC라면 별도 경로에 둔 동일한 개발용 키를
`-PpairDebugKeystore=C:/private/team-debug.keystore`로 두 프로젝트에 지정하세요.
이 옵션은 기본 debug 키 형식(androiddebugkey / android)을 사용하며 release에는 적용하지 않습니다.
키 파일은 Git에 올리지 않습니다. release는 별도로 같은 배포 서명 설정이 필요합니다.
`:app:signingReport`, `:wear:signingReport`의 debug SHA-256이 같아야 합니다.

수정한 워치 소스에는 `workersafety_watch` capability가 추가되어 있습니다.
기존 워치 APK는 앱 ID가 다르므로 업데이트 설치가 아닌 별도 앱으로 설치될 수 있습니다.
기존 워치 앱의 측정을 먼저 종료하고 새 앱을 실행하세요. 자동 삭제는 하지 않습니다.
워치 빌드에는 개발자가 공식적으로 받은 `samsung-health-sensor-api-1.4.1.aar`를
`wear/libs/`에 직접 배치해야 합니다. SDK 및 서명 키는 배포 소스에 포함하지 않습니다.

## 실기기 순서

1. Galaxy Wearable 등 기기 설정에서 Android 휴대폰과 지원 Galaxy Watch를 페어링합니다.
2. 동일 서명으로 빌드한 휴대폰 앱과 수정한 워치 앱을 각각 설치합니다.
3. 휴대폰 앱에서 실제 작업자 계정으로 로그인하고 워치 연결 새로고침을 누릅니다.
4. 로그인 후 워치에서 측정을 새로 시작하고, 센서 값을 받은 뒤 ‘지금 전송’을 누릅니다.
5. 휴대폰 홈에서 연결 상태, 평균 심박수, 피부온도, 측정 시각을 확인합니다.
6. 앱을 백그라운드로 보내고 다시 전송한 뒤 홈 복귀 시 최신 값이 표시되는지 확인합니다.
7. Bluetooth를 끊고 재연결합니다. Data Layer는 Wi-Fi/클라우드로 우회할 수 있으므로
   완전한 단절 시험에는 해당 경로도 끊어야 합니다. 연결 끊김 상태에서도 마지막 값과 시각을 표시합니다.
8. 재연결 후 새 요약이 갱신되는지 확인합니다. 측정 중지 후 주기+2분이 지나면 업데이트 지연을 표시합니다.
9. 로그아웃·다른 계정 로그인 후 이전 값이 표시되지 않는지 확인합니다.

## 수신과 상태

- `/workersafety/summary` DataItem의 5분 요약만 수신합니다. 워치 전송 간격을 5분으로 설정하세요. 10분 요약은 수락하지 않고 설정 안내를 표시합니다. 워치 앱 자체의 설정 변경은 이 휴대폰 저장소에 포함되지 않습니다.
- `WearableListenerService`로 백그라운드 데이터/연결 변경을 받고 최신 DataItem을 조회합니다.
- ViewModel이 살아 있는 동안 15초마다 연결과 최신 데이터를 확인하고, 홈 복귀/버튼에서도 확인합니다.
- 하나의 reachable `workersafety_watch` 노드만 사용합니다. 여러 개면 선택을 추정하지 않고 하나만 연결하도록 안내합니다.
- 로그인 중 처음 수신한 워치에 고정합니다. 다른 워치로 바뀌면 재로그인을 요구합니다.
- 심박수는 구간 평균, 피부/주변 온도는 해당 구간의 마지막 유효 샘플입니다. SpO2는 송신 데이터가 없어 표시하지 않습니다.
- 타입, 유효 플래그, 범위, 측정 개수, 시각을 검증하고 누락 센서는 0 대신 ‘측정값 없음’을 표시합니다.
- 직전 구간보다 앞서거나 겹치는 요약은 최신 값을 덮어쓰지 않습니다. 같은 ID와 데이터의 최신 요약이 재도착하면 보관 중인 수신 시각을 바꾸지 않고 다시 회신합니다. 주기+2분이 지나면 업데이트 지연으로 표시합니다.
- 토큰과 같은 수명의 메모리 저장소만 사용합니다. 화면 재생성에는 유지하고 프로세스 종료 후에는 재로그인·새 측정이 필요합니다.
- 수신·새로고침 도중 세션이 바뀌면 이전에 시작한 작업은 새 세션에 반영하거나 수락을 회신하지 않습니다.
- 로그인 시각 이전에 시작된 측정 구간은 거절합니다. 이미 측정 중이었다면 워치에서 측정을 중지·재시작하세요.
- 두 기기의 자동 날짜·시간을 활성화해야 합니다. 현재 프로토콜에 작업자/세션 ID가 없어
  시간 경계와 노드 고정으로 이전 측정을 걸러냅니다. 공유 워치의 엄밀한 계정 결합에는 이후 세션 ID 왕복 프로토콜이 필요합니다.
- 수신한 생체값을 서버로 전송하거나 생체 이상 SOS를 발생시키지는 않습니다.
- DataClient 쓰기 성공은 휴대폰 수신 확인이 아닙니다. 올바른 `summary_id`가 포함된 요약은 `/workersafety/summary/receipt`로 결과를 회신합니다. ID가 없는 구형 데이터는 회신 없이 수신할 수 있으며, 잘못된 ID가 들어 있으면 거절합니다.

`./gradlew --no-daemon :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug`

WatchSummaryTest: 실제 전송 형식, 센서 누락, 잘못된 형식/수치/미래 시각, 만료 표시,
중복·역순·재연결, 다른 워치 차단, 계정 변경/로그인 경계를 검사합니다.
실기기에서의 페어링, 백그라운드 수신, 삼성 SDK 센서 측정은 별도 확인해야 합니다.
